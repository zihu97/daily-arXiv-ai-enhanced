### [1] [WeightBridge: An Efficient Weight Transfer Library for Reinforcement Learning](https://arxiv.org/abs/2609.25442)
*Xuanlin Jiang,Samuel Hsia,Michael Kuchnik,Zachary DeVito,Minlan Yu,Carole-Jean Wu*

Main category: cs.DC

TL;DR: WeightBridge is a flexible, efficient weight‑transfer library that automatically matches trainer and rollout weight layouts, then transfers weights without redundancy while balancing load. It provides a small, general API and works across diverse RL configurations, reducing GPU stall time up to 42× compared to existing frameworks and integrating easily into different RL systems.


<details>
  <summary>Details</summary>
Motivation: Weight transfer is a major performance bottleneck in LLM RL pipelines due to the need to support varied trainer/rollout layouts and synchronization modes without sacrificing efficiency. Existing solutions are limited to specific configurations and often perform poorly elsewhere.

Method: WeightBridge employs an automatic correspondence extraction step to map trainer and rollout weight layouts, followed by planning and executing redundancy‑free, load‑balanced weight transfers. It offers a compact, generic API and coordinates workers across multiple synchronization modes, enabling seamless integration with diverse RL frameworks.

Result: Across a range of models, parallelization layouts, and synchronization modes, WeightBridge cuts average GPU stall time by as much as 42× over the state‑of‑the‑art open‑source RL framework and maintains high performance in every setting. A coding agent integrated WeightBridge into two distinct RL frameworks without manual guidance, confirming its generality and ease of use.

Conclusion: WeightBridge provides a scalable, efficient solution for weight transfer in modern LLM RL systems, overcoming layout and synchronization challenges while delivering substantial performance gains and easy integration.

Abstract: Weight transfer - the propagation of updated parameters from trainers to rollout generators - is becoming an important performance bottleneck in reinforcement learning (RL) systems for LLMs. The central challenge is supporting the diverse trainer and rollout layouts and synchronization requirements of modern RL workloads without sacrificing efficiency. Existing solutions are efficient under some configurations but perform poorly or lack support under others. We present WeightBridge, a flexible, efficient weight-transfer library designed to deliver high performance across diverse RL configurations. WeightBridge first automatically extracts the correspondence between trainer and rollout weight layouts, then plans and executes redundancy-free and load-balanced weight transfer. It exposes a small, general API while coordinating workers across diverse synchronization modes. Across configurations spanning different models, parallelization layouts, and synchronization modes, WeightBridge reduces average GPU stall time by up to 42$\times$ over the state-of-the-art open-source RL framework and achieves high performance in all settings. A coding agent was able to integrate WeightBridge into two different RL frameworks without manual guidance, demonstrating the generality and ease of use of its APIs.

### [2] [PatchKV: Efficient KV Cache Recovery for Dynamically Edited LLM Contexts](https://arxiv.org/abs/2609.26219)
*Guotao Yang,Rui Guo,Siwei He,Sheng Chen,Yitao Hu,Keqiu Li*

Main category: cs.DC

TL;DR: PatchKV is a profile-guided recovery system for LLM agent workflows that enables efficient revision of context spans by preserving suffixes and selectively restoring only modified portions, achieving significant speedups over full recomputation.


<details>
  <summary>Details</summary>
Motivation: In long-running LLM agent workflows, when interior context spans are revised while maintaining long suffixes, traditional approaches face challenges: suffix tokens remain unchanged but altered causal histories and rotary positions prevent exact reuse of KV states. Full suffix recomputation wastes prefill work, while indiscriminate reuse propagates stale states, and full-precision restoration adds unnecessary data movement.

Method: PatchKV decomposes adjacent context versions into an exact prefix, an updated span, and an aligned suffix. It uses an offline length-conditioned drift model to predict an edit-local dirty region, augments this region with sparse nonlocal blocks selected from stored attention, rounds their union into a fixed repair set, and restores remaining suffix blocks from CPU memory using frozen per-block precision tags along with a fused path for dequantization, RoPE correction, and KV-page placement.

Result: Across three models and three long-context QA workloads, PatchKV achieves 2.51-3.85× speedup in mean resume time-to-first-token compared to full suffix recomputation, and 1.26-2.06× speedup over CacheBlend. It matches or exceeds CacheBlend's F1 score in six of nine settings and remains within 1.36 points in the other three.

Conclusion: PatchKV effectively addresses the challenge of efficiently revising context spans in long-running LLM agent workflows by intelligently selecting only the necessary parts of the context for restoration, significantly reducing computational overhead while maintaining high accuracy comparable to existing methods like CacheBlend.

Abstract: Long-running LLM agent workflows often revise interior context spans while retaining long suffixes. Although suffix tokens remain unchanged, altered causal histories and rotary positions prevent exact reuse of their offloaded key-value (KV) states. Full suffix recomputation wastes prefill work, while indiscriminate reuse propagates stale states and full-precision restoration adds data movement. We present PatchKV, a profile-guided recovery system for suffix-preserving revisions. PatchKV decomposes adjacent context versions into an exact prefix, an updated span, and an aligned suffix. It predicts an edit-local dirty region using an offline length-conditioned drift model, augments this region with sparse nonlocal blocks selected from stored attention, and block-rounds their union into a fixed repair set. The remaining suffix blocks are restored from CPU memory using frozen per-block precision tags and a fused path for dequantization, RoPE correction, and KV-page placement. Across three models and three long-context question-answering workloads, PatchKV achieves a $2.51$-$3.85\times$ speedup in mean resume time-to-first-token over full suffix recomputation and a $1.26$-$2.06\times$ speedup over CacheBlend, while matching or exceeding CacheBlend's F1 score in six of nine settings and remaining within 1.36 points in the others.

### [3] [Accelerating the Mitigation of LLM Inference Nondeterminism Across GPU Architectures](https://arxiv.org/abs/2609.25624)
*Liam Cooper,Shinnung Jeong,Hyeran Jeon,Jeffrey Young,Hyesoon Kim*

Main category: cs.AR

TL;DR: 该论文提出一种固定配置的融合上转换GEMM内核，以实现跨GPU架构的线性层输出逐位相同，提升可重复性，同时提高性能。


<details>
  <summary>Details</summary>
Motivation: 大语言模型输出在不同GPU上因浮点非结合性和硬件相关核选择而不可重复，现有方法有缺陷且性能损失大。

Method: 使用固定配置的融合上转换GEMM内核，将16位权重加载到寄存器中转为FP32，用IEEE-754算术按问题形状决定的固定归约顺序进行累加，消除设备相关差异。

Result: 在NVIDIA Ampere、Ada、Hopper GPU上实现逐位相同的线性层输出，端到端速度比现有最优方案快1.17至3.1倍，权重内存流量减半。

Conclusion: 该方法实现了跨架构的精确可重复性，无需牺牲性能，为LLM推理提供了可靠且高效的解决方案。

Abstract: Large language model (LLM) outputs are expected to be reproducible under greedy decoding, yet in practice the same model, prompt, and software stack produce different outputs on different GPUs. The root cause is floating-point non-associativity combined with hardware-dependent kernel selection. Inference frameworks select different matrix-multiplication kernels on each architecture, with different parallel reduction orders and unspecified tensor-core arithmetic, and the resulting rounding differences can flip output tokens. Existing solutions have imperfect cross-architecture reproducibility and incur a significant performance penalty. We present a solution employing a set of fixed-configuration fused-upcast GEMM kernels that load 16-bit weights from memory, upcast them to FP32 in registers, and accumulate with IEEE-754 arithmetic in a reduction order that is a pure function of the problem shape and is therefore independent of the device, its SM count, or kernel scheduling. By fixing the floating-point reduction order as a function of problem shape alone, every GPU runs the same operation sequence, so cross-architecture reproducibility of the linear layers reduces to correct IEEE-754 arithmetic rather than to rounding differences staying below a tie-flip threshold. We confirm our solution's linear-layer outputs are bitwise identical across NVIDIA Ampere, Ada, and Hopper GPUs, while running $1.17$ to $3.1\times$ faster end-to-end than the state-of-the-art solution and cutting weight-memory traffic in half.

### [4] [Hot-Cold Tiering of HBM and High Bandwidth Flash for Agentic LLM Serving](https://arxiv.org/abs/2609.25782)
*Jongjin Baek,Won Ji,Seungjae Yoo,Joo-Young Kim*

Main category: cs.AR

TL;DR: 本文针对大语言模型（LLM）智能体多轮会话中KV缓存内存不足的问题，提出了一种基于高带宽闪存（HBF）和高带宽内存（HBM）的冷热分层KV缓存架构。通过将高频访问的热数据存入HBM、低频访问的冷数据存入HBF，显著提升了并发会话容量，并保持了低延迟与低功耗。


<details>
  <summary>Details</summary>
Motivation: 大语言模型（LLM）服务正越来越多地采用具有多轮会话的智能体（agentic）模式，这些会话在动作之间闲置但必须保留完整上下文。受限于GPU内存容量，非活跃的KV状态往往会被驱逐，导致恢复会话时需要承受高昂的重新计算成本或缓慢的跨节点数据传输。虽然高带宽闪存（HBF）提供了 orders-of-magnitude 更大的容量，但由于其高读取能耗和有限的写入寿命，无法单独承载所有KV流量。

Method: 研究发现，智能体KV状态的访问模式具有显著的冷热特征：一个小规模的热集（hot set）在每个解码步骤中都会被频繁读取，而一个大规模的冷池（cold pool）仅在暂停的会话恢复时才被读取。基于此，设计了GPU内存 tier 内的冷热分层KV缓存架构，将热集动态放置在HBM中，冷池放置在HBF中，实现冷热分离的协同存储。

Result: 在 Qwen3-Coder-30B-A3B 模型上的测试表明，该设计实现了 14 ms 的 token 间时间（TBT），在预填充（prefill）基础上仅增加了约 0.1 ms 的恢复延迟，同时每块 GPU 支持的并发会话数量提升了 24 倍。此外，通过将 HBM 限定用于热集，相比完全从闪存服务所有 KV 流量的方案，每 8-GPU 节点的读取功耗降低了 7.6 kW。

Conclusion: 高带宽闪存（HBF）应定位为 HBM 的冷级（cold-tier）补充，而非其替代品。通过冷热分层的 GPU 内存架构设计，不仅突破了大模型智能体服务的内存容量瓶颈，还实现了能效的显著提升，为构建高效、低功耗的下一代 LLM 推理系统提供了新路径。

Abstract: Large language model (LLM) serving is increasingly agentic, with multi-turn sessions that idle between actions yet must retain their full context. Limited GPU memory capacity forces inactive KV states to be evicted, so resuming a session incurs either costly recomputation or slow interconnect transfers. To address this, high bandwidth flash (HBF)-an on-package 3D-NAND memory offering orders-of-magnitude greater capacity than high bandwidth memory (HBM) at comparable read bandwidth-has emerged as a strong candidate. However, its high read energy and limited write endurance make it impractical to serve all KV traffic. Fortunately, our analysis shows that agentic KV states exhibit distinct access patterns: a small hot set is read for every decoding step, while a large cold pool is read only when a paused session resumes. Exploiting this, we place the hot set in HBM and the cold pool in HBF, forming a hot-cold KV hierarchy within the GPU memory tier. On agentic workloads with Qwen3-Coder-30B-A3B, our design delivers 14 ms time-between-tokens (TBT) and adds only $\approx$0.1 ms of resume latency on top of prefill, while hosting $24\times$ more concurrent sessions per GPU. By confining HBM to the hot set, our design also cuts read power by 7.6 kW per 8-GPU node relative to serving all KV from flash-establishing HBF as a cold-tier complement to HBM rather than its replacement.

</details>
