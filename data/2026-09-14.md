### [1] [Design and Operation of a Federated GPU Cluster for Digital Humanities within DHinfra.at](https://arxiv.org/abs/2609.10552)
*Florian Atzenhofer-Baumgartner,David Fleischhacker,Max Resch,Lukas Waldhofer,Michael Otto*

Main category: cs.DC

TL;DR: A technical report on the design and implementation of a small federated GPU cluster for Digital Humanities research in Austria, featuring a control plane for federated identity and model serving, released under Apache 2.0 with a build playbook.


<details>
  <summary>Details</summary>
Motivation: To provide accessible, collaborative GPU computing for Digital Humanities researchers across universities, enabling large language model inference without requiring direct cluster account management, within strict budget and staffing constraints.

Method: Implemented a control plane that integrates national identity federation, per-project quotas, and a model catalogue. Exposed compute via interactive notebooks, SSH, and an OpenAI-compatible API. Used a request-and-approval queue for privileged operations and a two-tier model-serving setup for on-demand LLM swapping.

Result: Successfully deployed a working cluster spanning two university sites. Documented the control plane, build constraints (power, procurement, team size), and key decisions. Produced a living technical report and a practical playbook for teams building similar budget-constrained GPU clusters.

Conclusion: The platform demonstrates a viable approach for domain-specific GPU clusters in academia under resource limitations. The accompanying playbook and open-source release (Apache 2.0) provide a reusable blueprint for similar initiatives.

Abstract: We describe the design, implementation, and operation of a small federated GPU cluster built for Digital Humanities (DH) research within the Austrian DHinfra.at project. The system spans two university sites, brokers logins from a national identity federation, and exposes compute through three interfaces: interactive notebooks, SSH, and an OpenAI-compatible inference API. The core of the platform is a control plane that maps federated identity, per-project quotas, and a model catalogue onto self-service interfaces. We document this control plane in detail, including the request-and-approval queue that mediates every privileged cluster effect and the two-tier model-serving setup, which combines always-on services with on-demand model swapping and lets researchers consume large language models over HTTPS without holding a cluster account. We report the constraints that shaped the build: a fixed power budget, EU-wide procurement, a team of about 1.5 full-time equivalents, and the relationship between prioritized access and utilization. We also record the main build decisions against the alternatives we researched and did not adopt. The platform is released under the Apache License 2.0. We close with a playbook for teams building a domain-specific GPU cluster on a limited budget. This is a living technical report, versioned and updated as the platform evolves.

### [2] [On the Relation between Code Quality and Machine Learning Performance: A Large-scale Empirical Study](https://arxiv.org/abs/2609.10610)
*Marius Mignard,Steven Costiou,Anne Etien*

Main category: cs.SE

TL;DR: 本研究考察了Kaggle竞赛的265,363个Python笔记本中代码质量与ML性能的关系，发现一般Python代码质量与ML性能无关，而ML特定违规与性能呈微弱负相关；流行度和代码专家均无法预测代码质量或性能。


<details>
  <summary>Details</summary>
Motivation: 在ML社区，模型性能常被视为主要指标，代码质量则被放在次要位置，这基于一个未经验证的假设：代码质量与ML性能无关。此外，实践者会重用来自社会信号（如流行度、作者专家）选择的笔记本代码，但这些信号作为质量代理的可靠性从未被评估。

Method: 研究对Kaggle竞赛中的265,363个Python笔记本进行大规模实证研究。使用Pylint评估一般Python代码质量，使用SonarQube（配置34条针对数据科学和ML实践的规则）评估代码质量。分析了代码质量、ML性能之间的关系，以及笔记本流行度和作者专业能力如何影响代码质量或性能。

Result: 一般Python代码质量与ML性能呈现可忽略或非显著的相关性，两者解耦。而ML特定违规则与性能呈一致的微弱负相关，且在所有观察中持续存在。笔记本的流行度无法预测代码质量或性能；代码专家也无法预测质量或性能，但竞赛专家与更好的性能、更少ML特定违规相关，且略微伴有更多Python错误和重构违规。

Conclusion: 代码质量与ML性能的关系依赖于所考虑的质量概念：一般Python质量与性能无关，ML特定实践违规与性能相关。流行度和代码专家均不适合作为质量或性能的代理指标；竞赛专家可能更值得信赖，尽管可能存在一定的代码质量问题。

Abstract: Context: Computational notebooks are the standard environment for machine learning (ML) development. Within the ML community, model performance is often the primary considered metric, and code quality is treated as a secondary concern. This prioritization relies on a largely untested assumption that code quality and ML performance are unrelated. Practitioners also reuse existing code that may come from notebooks selected through social signals (popularity, author expertise) whose reliability as quality proxies has never been assessed. Objective: We empirically investigated the relationship between code quality and ML performance in notebooks, and evaluated whether popularity and author expertise give indication on code quality or performance. Method: We conducted a large-scale empirical study of 265,363 Python notebooks submitted to Kaggle competitions. We assessed code quality with two static analysis tools: Pylint, capturing general Python code quality, and SonarQube, configured with a profile of 34 rules targeting data-science and ML-specific practices. Results: The relationship between code quality and performance depends on the notion of quality considered. General Python code quality is decoupled from ML performance, showing negligible or non-significant correlations across all observations. In contrast, ML-specific violations exhibit a consistent, small negative association with performance that persists across all observations. The popularity of a notebook does not give information on the code quality or performance. Code expertise provides no information on quality or performance, but competition expertise correlates with better performance, fewer ML-specific violations, and slightly more Python errors and refactoring violations.

### [3] [terms.txt: A Consent and Compensation Protocol for Agentic Web Access](https://arxiv.org/abs/2609.11152)
*Rajarshi Chowdhury*

Main category: cs.NI

TL;DR: 论文指出，AI爬取正在破坏传统开放网页“允许抓取、搜索引擎回流流量”的默契，并提出terms.txt与机器访问交换协议，让站点按路径和用途发布可执行、可审计的访问条款。


<details>
  <summary>Details</summary>
Motivation: 现有robots.txt只能声明是否允许抓取，无法表达身份、目的、授权、价格或合规边界；AI爬虫需求增长，导致站点希望控制训练和自动化访问，而现有替代方案多依赖专有CDN能力，缺乏开放、通用标准。

Method: 提出terms.txt，用于按路径和用途声明机器访问条款；配套Web Bot Auth签名、签名意图、委托令牌、HTTP 402协商和签名回执，并通过origin-enforced exchange在源站侧执行和审计访问决策。作者还实现了依赖免费的协议组件，并测量其请求延迟开销。

Result: 该方案可在不依赖专有CDN的前提下，为站点提供细粒度访问控制、意图声明、授权委托、费用协商和访问凭证审计；实现开销约为每次请求增加0.20至0.65毫秒。

Conclusion: 论文的核心贡献是把网页访问控制从简单的抓取许可扩展为可表达用途、身份、条件和审计要求的机器访问协议；但实际效果仍取决于AI平台、站点和基础设施是否广泛采用。

Abstract: The open web ran on an unwritten bargain: sites admitted crawlers, and search engines sent visitors back. Public measurements show that bargain breaking under AI crawlers and agents. Automated clients now make up most requests, training dominates Cloudflare-classified crawling, and the largest AI platforms fetch thousands of pages for each visitor they return. The web's common control, robots.txt, cannot express identity, purpose, terms, or price, can be circumvented, and newer alternatives are largely proprietary CDN features. We specify terms.txt, a robots.txt-style file for per-path, per-purpose machine-access terms, plus an origin-enforced exchange using Web Bot Auth signatures, signed intent, delegation tokens, HTTP 402 negotiation, and signed receipts. We define what the exchange can enforce, audit, and leave to contract. A dependency-free implementation adds 0.20 to 0.65 ms per request on one vCPU.

</details>
